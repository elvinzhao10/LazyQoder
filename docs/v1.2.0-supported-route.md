# LazyQoder v1.2.0: supported route

v1.2.0 is prepared for release, but it is not published yet. It is not a
marketplace publication.

1. After v1.2.0 is published, clone its release tag and use its durable
   lifecycle entrypoint:

   ```bash
   git clone --branch v1.2.0 https://github.com/elvinzhao10/LazyQoder.git
   node "<checkout>/lazyqoder-plugin/scripts/lazyqoder-lifecycle.js" onboard \
     --source https://github.com/elvinzhao10/LazyQoder/releases/tag/v1.2.0 \
     --install-root "<absolute-install-root>" --project "<absolute-project-root>" --json
   ```

2. Use the installed launcher for package checks:

   ```bash
   node "<install-root>/LazyQoder/launcher.js" status \
     --install-root "<install-root>" --project "<project-root>" --json
   ```

3. Choose one host route. For Qoder CLI and Qoder IDE with the CLI
   available, add the launcher-reported release root as a local marketplace and
   install `lazyqoder@lazyqoder`. For Qoder, choose the release-local
   `lazyqoder-plugin` directory containing `.qoder-plugin/plugin.json` in
   the current build's visible plugin/marketplace flow.

4. Start a fresh host session. Package checks prove package readiness only.
   Host readiness requires a visible LazyQoder Skill or command and all six MCP
   servers: `run-ledger`, `verification`, `status-dashboard`, `context-graph`,
   `code-intel`, and `docs`.

The Skills/manual-MCP route is recovery-only and cannot coexist with the full
plugin route for the same project. Do not publish a marketplace artifact or
claim host readiness without fresh-session evidence.
