# LazyQoder Build Conventions (SHARED — every build agent MUST read this first)

You are porting the **LazyBuddy** CodeBuddy/WorkBuddy plugin into **LazyQoder**, the
4th port of the LazyCodex host-port family, targeting **Qoder IDE** (Alibaba's
successor to Tongyi Lingma). Output goes ONLY under
`/Users/Admin/Desktop/lazyqoder/LazyQoder/`. The three source repos
(`LazyBuddy/`, `LazyTrae/`, `lazycodex/`) under `/Users/Admin/Desktop/lazyqoder/`
are READ-ONLY — never modify them.

## MANDATORY RENAME MAP (apply everywhere in content + filenames)
- `lazybuddy` → `lazyqoder` (identifiers, filenames `lazybuddy_*`→`lazyqoder_*`, env/paths)
- skill/command prefix `lazy-` → `qoder-`  (e.g. `lazy-init-deep` → `qoder-init-deep`)
- agent name `lazybuddy-*` → `lazyqoder-*`  (e.g. `lazybuddy-orchestrator` → `lazyqoder-orchestrator`)
- `CODEBUDDY_PLUGIN_ROOT` → `QODER_PLUGIN_ROOT`
- `WORKBUDDY` / `CodeBuddy` / `WorkBuddy` / `Trae` host coupling → `Qoder IDE`
- `.codebuddy-plugin` / `.workbuddy-plugin` → `.qoder`
- `lazybuddy-plugin` path references → `lazyqoder-plugin`
- command invocations `/lazybuddy:lazy-X` → `/lazyqoder:qoder-X`
- internal python record `host: "lazybuddy"` → `"lazyqoder"` (and the matching `validate()` expectation)
- `.lazybuddy-*` receipt filenames referenced in python → `.lazyqoder-*`

## DO NOT
- Do NOT modify the source repos (read-only).
- Do NOT change the two contract JSON files' CONTENTS (they are copied verbatim with their
  `.sha256` sidecars by the contracts agent; their sha256 is load-check-verified).
- Do NOT write literal `process.env` or `import.meta.env` substrings (a pre-write safety
  hook blocks them). Use bracket notation `process["env"]` or a constant if an env
  accessor is genuinely needed.

## Qoder IDE CAPABILITY MAPPING (inject where each primitive is described)
| Harness primitive | Qoder IDE native feature |
| --- | --- |
| `init-deep` (hierarchical memory) | **RepoWiki** (auto, always-synced code wiki) + a `qoder-init-deep` skill/rule |
| `ulw-plan` (decision-complete plan) | **Quest mode** (auto tech-design/spec) |
| `start-work` / `ulw-loop` (durable execution) | **Agent mode + Subagents** (long-running Agent mode + Subagents (Qoder IDE cites end-to-end delivery on multi-hour, whole-repo tasks such as a 26-hour refactor; Repowiki/Quest/Subagent usage is unlimited)) |
| `review-work` / `reviewer` / `verifier` | **Expert teams** (领域专家智能体: frontend/backend/db/ops/test) |

| MCP servers (code-intel, lsp, …) | **Agent mode MCP** tool connections |

When a skill/command/agent describes one of these primitives, add a short note mapping it
to the Qoder IDE feature (e.g. "Maps to Qoder IDE RepoWiki"). Keep the original
semantics; do not strip functionality.
